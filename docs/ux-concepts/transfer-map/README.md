# 연결 그래픽 시안 (2026-10-15, 2차)

1차 목록형 시안([transfer-radar](../transfer-radar/))을 본 뒤 받은 방향에 따라 다시 만든 그래프형 시안 3종입니다. 04 시간 리본은 사용자 의견("완전 별로")에 따라 제외했습니다.

> 이후 사용자가 그래프가 아닌 그래픽을 요청해 3차 시안 [transfer-board](../transfer-board/)를 만들었습니다.

> 사용자 요청: UI는 아주 단순하게, 마인드맵처럼 구단과 선수의 연결을 선의 종류(점선, 실선 등)와 색으로 구분하고, 글자는 최소로. 핵심은 연결 그래픽을 세련되게 만드는 것. 그래픽에 초점을 맞춘 방식을 더 제안할 것.

| 폴더 | 그래픽 | 한 줄 요약 |
| --- | --- | --- |
| [concept-01](concept-01/) | 마인드맵 가지형 | 가운데 구단에서 왼쪽(영입)·오른쪽(방출)으로 S자 가지가 뻗고, 가지 끝에 상대 구단이 달린다 |
| [concept-02](concept-02/) | 리그 네트워크 | 시즌 구단 전체를 원 위에 고정하고, 이적 건을 구단 사이의 휜 선으로 잇는다. 고른 구단의 선만 밝다 |
| [concept-03](concept-03/) | 레이더 궤도 | 동심원 하나가 주장된 단계 하나. 진전될수록 선수가 구단에 다가오고, 공식 확정만 중심 고리에 닿는다 |
| shared | 공통 그래픽 | `map.js`(선 인코딩, 곡선, 노드, 강조, 카드, 범례), `map.css`, `shell.js`(얇은 막대, 상태, 카드, 주소 상태) |

구단명은 실제 K리그 구단(예시 배치, 실제 시즌 승강과 무관), 선수·이적 주장·출처는 모두 가상입니다. 데이터, 의미 토큰, 상태 문구, 검토 도구는 1차 시안의 `../transfer-radar/shared/`를 그대로 씁니다.

## 실행 방법

```powershell
python -m http.server 8731 --bind 127.0.0.1
# http://127.0.0.1:8731/docs/ux-concepts/transfer-map/concept-01/index.html
```

검토 도구(오른쪽 아래)에서 시안, 폭, 라이트/다크, 정지 화면, 데이터 묶음, 상태를 바꿀 수 있습니다. `?embed=1`을 붙이면 도구가 숨겨집니다.

## 공통 선 언어

"루머가 사실로 굳어 간다"는 하나의 은유로 모든 선을 그립니다.

| 단계 | 선 | 색 |
| --- | --- | --- |
| 단계 미확인 | 아주 듬성한 구슬 | 회색 |
| 관심설 | 듬성한 구슬 | 회청색 |
| 접촉설 | 촘촘한 구슬 | 파랑 |
| 협상설 | 짧은 대시 | 호박색 |
| 합의 임박설 | 긴 대시(거의 이어짐) | 보라 |
| **공식 확정** | **실선 + 옅은 후광** | **초록 (이 경우에만)** |
| 결렬설 | 끊어지는 짧은 점선 + × 표시, 끝으로 갈수록 사라짐 | 빨강 |

- **굵기 = 근거 신뢰도**: 낮음 2px, 보통 3px, 높음 4.4px. 확률이 아니라는 설명은 범례와 카드에 있습니다.
- **방향**: 선은 출발 쪽이 옅고 도착 쪽이 진한 그라데이션입니다. 진행 중인 루머는 구슬이 도착 방향으로 천천히 흐릅니다. 공식 확정과 결렬은 멈춰 있습니다. `prefers-reduced-motion`과 정지 화면에서는 모든 흐름이 멈춥니다.
- **선수 점의 표시**: 검토 대기는 점 둘레를 천천히 도는 주황 점선 고리, 반박됨은 흐린 점에 빨간 사선, 선수 미확정은 점선 테두리의 빈 점, 공식 확정은 초록 점에 체크입니다.
- **집중**: 선이나 점에 마우스를 올리거나 키보드 포커스를 주면 그 연결만 남고 나머지는 10% 밝기로 물러납니다. 누르면 카드가 고정됩니다.
- **글자**: 화면에 늘 보이는 글자는 구단 약칭과 선수 이름, "영입/방출" 정도입니다. 단계 이름, 신뢰도, 검토 상태, 출처, 시각은 카드를 열 때만 나옵니다. 카드의 "근거 n건 보기"에서 출처별 주장과 원문 링크를 봅니다.
- **접근성**: 모든 점과 구단은 키보드로 갈 수 있고, 각 점의 접근 가능한 이름은 "문태오, 부산 아이파크에서 울산 HD FC로, 협상설, 신뢰도 낮음, 검토 대기"처럼 전체 의미를 담습니다. 막대의 목록 버튼은 같은 내용을 글 목록으로 보여 줍니다. 색을 구별하지 못해도 선 모양과 점 표시로 단계가 구분됩니다.

## 시안별 설명

### 01 마인드맵 가지형

- 첫 화면: 가운데 구단 원. 왼쪽 가지는 영입, 오른쪽 가지는 방출. 가지마다 선수 점을 거쳐 상대 구단 원으로 이어진다. 같은 상대 구단에서 온 선수끼리 묶어 가지가 교차하지 않는다.
- 세로 화면: 위가 영입, 아래가 방출.
- 장점: 요청한 그림과 가장 가깝다. 한 구단의 영입·방출 전체가 한 장에 들어온다. 처음 보는 사람도 바로 읽는다.
- 단점: 방향마다 9건(세로 6건)이 넘으면 "+N" 점으로 접힌다(대량 데이터에서 확인). 시간 정보가 없다.
- 구현 부담: 하. SVG와 곡선 계산만.

### 02 리그 네트워크

- 첫 화면: 원 위에 K리그1(왼쪽 호), K리그2(오른쪽 호) 구단이 고정 자리에 있다. 고른 구단의 선과 선수 이름만 밝고, 나머지 리그의 이적은 옅은 거미줄로 보인다. 원 위 구단을 누르면 바로 그 구단으로 바뀐다.
- 장점: 리그 전체 시장 흐름과 구단 사이 관계(같은 두 구단 사이 여러 건 등)를 함께 본다. 구단 위치가 바뀌지 않아 익숙해지면 빠르다.
- 단점: 한 구단에 소식이 몰리면 선이 한쪽으로 쏠린다(합성 데이터에서 그렇다). 모바일에서는 원이 작다.
- 구현 부담: 중. 리그 전체 목록 조회(`club_id` 없이)는 계약 1.0으로 가능.

### 03 레이더 궤도

- 첫 화면: 레이더 원. 안쪽부터 공식 확정, 합의 임박설, 협상설, 접촉설, 관심설, 단계 미확인 궤도, 가장 바깥에 결렬설 점선 궤도. 왼쪽 반원은 영입, 오른쪽 반원은 방출. 상대 구단 이름은 테두리 밖에 있다.
- 탐지 부채꼴: 서버가 정상 갱신 중(`pipeline_status = ready`)일 때만 천천히 돈다. 지연·중단·보관 시장에서는 멈춘다. 장식이 아니라 갱신 상태 표시다. 세로 화면에서는 끈다.
- 세로 화면: 원을 세로로 늘린 타원으로 그리고, 궤도 이름은 범례로 대신한다.
- 장점: 서비스 이름과 그래픽이 일치한다. "얼마나 가까이 왔나"가 거리로 읽힌다.
- 단점: 거리로 표현하면 단계가 순서대로 진행된다는 인상을 줄 수 있다(계약상 단계는 자동 승격 순서가 아니다). 같은 궤도에 몰리면 이름이 겹친다.
- 구현 부담: 중.

## 추천: 01 마인드맵 가지형 + 03의 궤도 감각

- 요청에 가장 가깝고, 모바일에서 가장 잘 읽히며, 공개 API 1.0만으로 만들 수 있습니다.
- 03의 "탐지 부채꼴 = 갱신 상태" 아이디어는 01의 중심 구단 원 둘레에 옮겨 쓸 수 있습니다.

## 확인한 것

- 시안(당시 4종) × 라이트·다크 × 1440·768·390·320 폭, 그리고 대량 134건·지난 시장·서버 오류·0건 상태에서 가로 넘침 0, 콘솔 오류 0. 320 폭 레이더에서 테두리 구단 이름이 잘리던 것을 고쳤다.
- 선택(카드 열기), 포커스 강조, 근거 펼치기를 01·02에서 눌러 확인했다.
- impeccable 디텍터: 03의 캔버스 라벨 글자 크기 단계(10/12.5/16px)에 "단계 간격이 좁다" 경고 1건이 남았습니다. 다른 시안은 0건입니다.
- 확인하지 못한 것: 스크린 리더 실기, 실제 터치 기기, 200% 확대, 리그 전체 규모의 실데이터.

## 남은 결정

1. 고를 시안(또는 조합).
2. 01·03에서 방향마다 몇 건까지 펼치고 나머지를 어떻게 접을지.
3. 흐르는 구슬 모션의 속도와 기본 켜짐 여부.
4. 03에서 거리 표현이 "단계가 순서대로 진행된다"는 오해를 줄지, 짧은 사용성 확인 필요.
5. 한국어 표시명, 구단 엠블럼 사용 여부(1차 시안과 같음).
