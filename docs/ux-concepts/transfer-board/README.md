# 선 없는 그래픽 시안 (2026-10-15, 3차)

**선호: 5 배송 조회** (2026-10-15, 사용자 의견 "배송조회 좋다". 최종 선택 확정 전)

### 5 배송 조회 보완 (2026-10-15, 사용자 "추천대로")

- **목록**: 현재 위치를 큰 점과 단계 이름으로 표시. 검토 중인 상충 주장은 막대를 움직이지 않고, 그 주장이 가리키는 역에 주황 점선 고리(결렬 주장은 ×)와 "결렬 주장 검토 중" 꼬리표로 표시. 진행 중 / 확정 / 결렬·반박 묶음과 같은 이름의 보기 필터.
- **상세**: 택배 조회의 배송 이력처럼 "조회 이력"을 최신순으로 쌓음. 단계 반영(검은 점), 출처 주장(빈 점), 검토 중 주장(주황 점선, "검토가 끝나기 전까지 현재 위치는 바뀌지 않습니다"), 공식 발표 확인(초록). 재게시가 3건 이상 이어지면 "재게시 n건 펼치기"로 접음. 각 줄에 원문 링크 또는 "원문 삭제·접근 불가".
- 데스크톱에서 상세가 열리면 목록이 옆으로 비켜남.
- **추가 필드 요구**: 목록의 주황 고리와 꼬리표는 검토 중인 주장의 `claimed_stage`가 목록 응답에 있어야 그릴 수 있다(시안은 합성 데이터에서 직접 읽음). 예: `pending_claims: [{ claimed_stage, analyzed_at }]`.

사용자 요청: 그래프(노드와 연결선) 말고 다른 그래픽, 아예 다른 콘셉트도 가능. 이어서 그래프형 3종([transfer-map](../transfer-map/))과 합쳐 **총 10종**.

모든 시안에서 같은 규칙을 지킵니다: 초록은 공식 확정에만, 점선·옅은 채움은 출처의 주장, 신뢰도는 확률로 표현하지 않음, 검토 대기는 주황 표시, 화면의 기본 글자는 이름 정도이고 자세한 내용은 선택 시 카드에서.

## 제외한 시안

- 스티커 앨범, 전술판: 만들었으나 사용자 의견("별로")으로 삭제.
- 시간 리본(2차 04): 사용자 의견으로 삭제.

## 실행

```powershell
python -m http.server 8731 --bind 127.0.0.1
# http://127.0.0.1:8731/docs/ux-concepts/transfer-board/concept-01/index.html
```

검토 도구(오른쪽 아래)의 "시안" 줄에서 1~10을 바로 오갑니다. `file://`로 직접 열어도 동작합니다.

## 공통 부품

- `shared/board.js`, `board.css`: 진행 고리 토큰, 포지션 묶음, 구단 약칭
- `shared/steps.js`: 단계 순서, 아바타 원(점선 = 주장, 초록 실선 = 확정), 신뢰도 점
- 셸(막대, 카드, 범례, 글 목록, 상태)은 `../transfer-map/shared/shell.js`를 `dom: true`로 씁니다.

## 확인한 것

- 10종 × 라이트·다크 × 1440·768·390·320 폭 × 기본·대량·오류·0건·지난 시장 묶음(184 조합)에서 페이지 가로 넘침 0, 스크립트 오류 0. 측정 뒤 잘림이 나온 두 곳(레이더 대량 390폭의 이름, 버블 대량 320폭의 거품)을 고쳤고, 고친 뒤 다시 재지는 않았다.
- 4~10의 데스크톱·모바일 스크린샷을 직접 확인했다.
- 확인하지 못한 것: 스크린 리더 실기, 실제 터치 스와이프(10 카드 덱), 200% 확대.

## 남은 결정

1. 10종 중 방향 고르기(또는 조합).
2. 5·6·7처럼 단계를 순서 있는 진행으로 그리는 방식이 "단계는 자동 승격 순서가 아니다"라는 계약 원칙과 충돌하지 않는지 사용성 확인.
3. 8·9에서 크기를 독립 출처 수로 쓰는 것이 "출처가 많으면 사실"로 읽히지 않는지 확인.
