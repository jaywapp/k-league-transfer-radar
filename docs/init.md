# K-League Transfer Radar — 초기 MVP 기획

## 1. 한 줄 요약
에펨코리아의 K리그 이적 루머를 수집·AI 분석해 K리그1·2 전체 구단의 영입·방출 연결 선수, 주장된 협상 단계, 정보 신뢰도와 근거를 이적시장별로 보여주는 서비스.

## 2. 배경 및 문제
팬들은 커뮤니티 게시판을 반복 방문해 흩어진 루머를 직접 확인한다. 같은 선수의 여러 게시글을 비교하고 진척·결렬·공식 발표를 추적하기 어렵다. 게시글 수가 많다는 이유만으로 신뢰도가 높은 것처럼 오해할 수도 있다.

## 3. 목표
- 구단 선택만으로 해당 시장의 영입·방출 루머를 한눈에 확인한다.
- 각 주장에 원문 링크, 신뢰도, 검토 상태를 제공한다.
- 동일 이적 건의 변화 이력을 누적하되 근거 없는 확정을 방지한다.
- 실제 수집 가능성 및 AI 분석 정확도를 PoC로 검증한다.

## 4. 대상 사용자
- **K리그 팬:** 관심 구단의 이적 루머와 변화 확인.
- **운영 관리자:** 모호하거나 상충하는 분석만 검토·정정.

## 5. 핵심 아이디어 및 확정 정책
| 구분 | 확정 |
|---|---|
| 프로젝트명 | K-League Transfer Radar (`k-league-transfer-radar`) |
| 대상 | K리그1·2 전체 구단 |
| 초기 출처 | 에펨코리아 우선 |
| 처리 | 서버 수집 → AI 분석 → 이적 건 통합 |
| 공개 | 분석된 이적 루머는 신뢰도와 관계없이 공개 |
| 검토 | 불확실·충돌 건만 관리자 검토 |
| 검토 대기 | 즉시 공개하되 '검토 대기' 표기, 기존 상태 유지 |
| 영입 확정 | 구단·리그 공식 발표를 확인한 경우에만 초록색 |
| 관리 단위 | 겨울·여름 이적시장별 별도 이적 건 |
| 지난 시장 | 읽기 전용 보관 |

'모두 공개'는 **이적 루머로 분류된 주장**에 적용하며 농담·단순 희망·무관한 게시글은 포함하지 않는다. 협상 단계는 **게시글의 주장**이지 검증된 사실이 아니다.

## 6. 주요 사용 흐름
1. 사용자가 시즌/겨울·여름 시장과 K리그1·2 구단을 선택한다.
2. 영입/방출 목록에서 선수, 연결 구단, 주장된 단계, 신뢰도, 최신 갱신 시각을 확인한다.
3. 선수별 상세 화면에서 원문·근거·타임라인·검토 상태를 확인한다.
4. 서버는 신규 게시글을 수집하고 중복 URL을 제거한다.
5. AI가 루머 여부, 선수·구단·방향·주장 단계·근거를 추출한다.
6. 기존 이적 건에 연결하거나 새 건을 만든다. 명확하면 자동 반영하고 모호·충돌하면 잠정 주장만 공개한 뒤 검토 대기열에 등록한다.
7. 관리자는 예외 건을 승인·수정·반려하고 변경 이력을 남긴다.

## 7. 핵심 기능 (MVP)
| ID | 기능 | 핵심 처리 | 우선순위 |
|---|---|---|---|
| F1 | 게시글 수집 | 신규 글 탐색, URL 중복 제거, 원문 링크·시각 보존, 실패 재시도 | 필수 |
| F2 | AI 루머 분석 | 루머 분류, 선수/구단/방향/주장 단계/근거 추출 | 필수 |
| F3 | 이적 건 통합 | 동일 시장·선수·연결 구단 기준 연결, 중복 주장 구분, 이력 유지 | 필수 |
| F4 | 구단별 현황판 | 시장·구단·영입/방출별 목록, 단계·신뢰도·출처 표시 | 필수 |
| F5 | 예외 검토 | 불확실·충돌 검토 대기열, 승인/수정/반려, 감사 이력 | 필수 |
| F6 | 공식 확정 처리 | 공식 발표 확인 시에만 확정·초록색 표시 | 필수 |
| F7 | 시장 아카이브 | 시장 종료 시 읽기 전용 조회 | 필수 |

### 상태 모델 (AI 제안: 세부값 미확정)
- **주장된 단계:** 관심설(회색), 접촉(파랑), 협상(노랑), 합의 임박(보라), 영입 확정(초록), 결렬(빨강).
- **신뢰도:** 낮음/보통/높음. 근거 출처의 독립성·명확성을 반영하며 게시글 수만으로 상승시키지 않는다.
- **검토 상태:** 미검증/검토 대기/검토 완료/반박됨 등의 후보. 구체적인 전이 규칙은 구현 전 검증한다.
- **중요:** 단계·신뢰도·검토 상태는 별도 필드다. '합의 임박' 주장이라도 신뢰도 낮음/검토 대기일 수 있다.

## 8. 데이터 및 연동 (논리 모델 제안)
| 엔터티 | 주요 필드 | 역할 |
|---|---|---|
| TransferWindow | id, season, type(winter/summer), starts_at, ends_at, archived_at | 시장별 분리·보관 |
| Club | id, name, league, season | 구단 식별 |
| Player | id, name, aliases, position, current_club_id? | 선수 식별·동명이인 처리 |
| TransferCase | id, window_id, player_id?, from_club_id?, to_club_id?, direction, claimed_stage, confidence, review_status, updated_at | 선수-구단-시장별 이적 건 |
| RumorSource | id, url, title, posted_at, collected_at, availability | 원문 메타데이터 |
| RumorEvidence | id, case_id, source_id, claim, excerpt?, source_relation, analyzed_at | 이적 건과 원문 간 다대다 연결·주장 근거 |
| ReviewTask | id, case_id?, evidence_id?, reason, proposed_change, status, resolved_at | 예외 검토 |
| StatusHistory | id, case_id, before, after, reason, evidence_id?, actor, changed_at | 변경 감사 이력 |

이는 DB 제품·물리 스키마 확정이 아닌 **논리 구조**다. 선수/구단 미식별 시 임의 병합하지 않고 검토 대상으로 둔다. 공식 발표의 확인 링크·시각도 근거로 남긴다.

## 9. 처리 흐름 및 예외
**수집 → 중복 검사 → 1차 분류 → AI 구조화 → 선수/구단 식별 → 이적 건 매칭 → 충돌 검사 → 자동 반영 또는 검토 대기 → 현황판 갱신**

| 상황 | 처리 원칙 |
|---|---|
| 동일 URL 재수집 | 중복 생성 금지 |
| 동일 주장 재게시·인용 | 근거 관계 보존, 독립 출처로 중복 가중하지 않음 |
| 상반된 루머 | 양측 주장 공개, 기존 단계 유지, 검토 요청 |
| 동명이인·팀 불명 | 임의 병합·상태 변경 금지, 검토 요청 |
| 복수 구단 연결 | 연결 구단별 이적 건 분리 |
| 게시글 삭제 | 접근 불가 표시; 보존 범위·권리 검토 |
| 결렬 뒤 재협상 | 이력 유지, 새 주장 근거 기록 및 필요 시 검토 |
| AI 실패 | 제한된 재시도 후 실패 대기열 |
| 공식 발표와 루머 충돌 | 공식 자료 우선, 변경 이력 보존 |
| 시장 종료 | 읽기 전용 아카이브; 다음 시장은 새 건 생성, 이전 이력 참조 가능 |

## 10. 범위
### MVP
K리그1·2 구단/시장 선택, 에펨코리아 기반 수집·AI 분석, 선수별 통합, 단계·신뢰도·근거·이력, 예외 관리자 검토, 공식 확정, 지난 시장 조회.

### Later
다른 언론·커뮤니티 수집, 관심 구단 개인화, 푸시 알림, 선수 통계·이적료 분석, 해외 리그 확장.

### Out of Scope
초기 회원가입/개인화, 이적 가능성을 확률로 단정하는 예측, 공식 발표 없는 자동 영입 확정.

## 11. 검증 기준 (AI 제안 목표, 미확정)
실제 게시글 약 100~200건을 사람이 라벨링해 평가. 분류 정확도 외 **루머 재현율**과 자동 변경의 오류율도 별도 확인한다.

| 항목 | 초기 제안 목표 |
|---|---|
| 루머 분류 정확도 | 90% 이상 |
| 선수·구단 추출 정확도 | 95% 이상 |
| 이적 건 병합 정확도 | 95% 이상 |
| 명백한 충돌의 검토 전환율 | 95% 이상 |
| 공식 근거 없는 확정 | 0건 |
| 수집·분석 처리 성공률 | 95% 이상 |
| 공개 루머의 원문 링크 보유 | 100% |

위 수치는 PoC에서 조정 가능하며 현재 달성된 결과가 아니다.

## 12. 위험 요소 및 대응
- **수집 정책·차단:** 에펨코리아 이용약관, robots/접근 정책 및 기술적 허용 범위 검증. 우회 수집을 전제하지 않음.
- **오정보·명예/저작권:** 주장과 사실을 분리, 원문 링크 중심 제공, 과도한 원문 복제 지양, 정정·삭제 대응 설계.
- **AI 환각:** 근거 없는 단계 승격 금지, 모호한 식별 검토 전환, 변경 이력 보존.
- **비용·지연:** 규칙 기반 사전 필터, 중복 분석 방지, 주기·모델 비용 실측.
- **공식 발표 확인:** 공식 구단/리그 출처 접근 방법 및 자동 검증 가능성 미확정.

## 13. 결정된 사항
K리그1·2 전체 / 에펨코리아 우선 / AI 분석 / 루머 모두 공개 및 신뢰도 구분 / 불확실·충돌만 검토 / 검토 대기 즉시 공개 및 기존 상태 유지 / 공식 발표 확인 시만 확정 / 시장별 분리 / 종료 시장 읽기 전용.

## 14. 미결정 사항
1. 겨울·여름 **루머 추적 기간**의 정확한 경계(공식 등록 기간과 구별).
2. 에펨코리아 수집 허용 여부·수단·주기·장애 대응.
3. AI 모델, 신뢰도 산정 규칙, 검토 임계값 및 운영 비용.
4. 공식 발표 확인 경로·증빙 규칙·검토 권한.
5. 실제 평가 데이터·정답 기준과 목표치 최종 승인.
6. 배포·DB·관리자 인증 방식.
